# Writing a project the posting needs (Sai builds it later)

For a project slot that no Built project fills (rule 7, rule 10). It goes straight onto the resume; Sai builds it
himself if the posting calls, so nothing is created in Notion. Its lines must still survive "walk me through this
project", so design it as something real and specific.

1. **Reuse first.** A Projects row with Status Planned whose subject is this posting's core problem may be reused:
   use its resume lines as a starting point. Otherwise design a new one.
2. **Design** around the posting's core problem:
   - **Problem:** the core problem, scaled to a portfolio project.
   - **Data:** a public dataset that exists today, named and linked (Kaggle, UCI, data.gov, a public API). Look it
     up; a dataset you cannot link is not chosen.
   - **Method and stack:** the posting's required tools first, then preferred ones; the techniques that answer the
     core problem.
   - **Evaluation:** the metric and the baseline it is judged against.
3. **Write the resume lines** under the content rules in `SKILL.md`: finished-work voice, the result clause names the
   metric with no number, no repo link.
4. **List it in the delivery note** under "Projects to build": name, dataset link, stack, the exact resume lines.
