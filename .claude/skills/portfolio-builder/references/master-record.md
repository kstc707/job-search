# Master record format

The master record frames Sai's real work for every role family. It holds no facts of its own:
facts and numbers live on the experience pages and project pages of the Resume Knowledge Base,
and each cell here only says how that work reads for one role.

## Role families (columns)
- **DA/BI**: data analyst, BI, reporting, business analyst
- **DS**: data scientist, product/decision science, experimentation
- **ML/AI**: ML engineer, AI engineer, applied AI, LLM and agent roles
- **SWE**: software engineer, automation, internal tools
- **DE**: data engineer, analytics engineer

## Sections
1. **Experience**: one row per distinct piece of work at a job (not one row per job).
2. **Built projects**: one row per Built project, or per group of small related projects.
3. **Industry vocabulary: where it is already true**: concept (with the blueprint that uses the
   term) → the rows where Sai's work genuinely is that thing.
4. **Not yet true**: concepts postings ask for that no row supports yet; these feed the Gap
   Ledger and the build queue.
5. **Build queue**: Planned projects and their blueprints.

## Cell rules
- A cell describes the same work in that role's words; it never adds scope, scale, users or
  numbers the source page does not have. Numbers, when used, are copied from the source page.
- Use "-" when the work does not speak to that role.
- Industry vocabulary ("feature store", "model monitoring", "experimentation framework",
  "structured extraction") goes in a cell only when the work actually is that thing.
- Shelby County District Attorney work: structural counts only (streams, record types,
  on-premises), never case counts or rates.

## Using it for a resume
Pick the posting's role family, take that column, and lead with the rows that answer the
posting's core problem; the resume skill writes the bullets from the source pages.
